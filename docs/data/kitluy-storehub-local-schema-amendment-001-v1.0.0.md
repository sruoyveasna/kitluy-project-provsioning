## 2. Sync-state mapping (KLREQ-021)

Persisted database state and wire vocabulary are reconciled explicitly, not merged.

| Concept                 | Persisted (`edge_sync.delivery_state`) | Wire (`sync_state`)  | Owner                                 |
| ----------------------- | -------------------------------------- | -------------------- | ------------------------------------- |
| committed locally       | `pending`                              | `pending_cloud_sync` | WS-09 (this cycle)                    |
| pending transmission    | `pending`                              | `pending_cloud_sync` | WS-09 records; WS-10 acts             |
| transmitted             | `sending`                              | `pending_cloud_sync` | **WS-10** — WS-09 never sets this     |
| acknowledged            | `acknowledged`                         | (WS-10 vocabulary)   | **WS-10** — WS-09 never fabricates it |
| rejected                | `blocked` / `dead_letter`              | (WS-10 vocabulary)   | **WS-10**                             |
| reconciliation required | `edge_sync.conflict_state = 'open'`    | (WS-10 vocabulary)   | **WS-10**                             |
| retry waiting           | `retry_wait`                           | (WS-10 vocabulary)   | **WS-10**                             |

WS-09 writes only `pending` and reports only `pending_cloud_sync`. Any other
persisted delivery state written by WS-09 would be a fabricated cloud outcome.
