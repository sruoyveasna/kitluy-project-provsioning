## 8. Decision rationale

Verdict: **PASS-WITH-CONDITIONS**.

The custody-critical claims all verify:

1. **Exact fidelity to the drawn models.** Both state vocabularies are verbatim (including the awkward-but-canonical `CONFIRMED/FINALIZED`, `FULFILLED/COMPLETED`, `RETURN/REFUND` and the lowercase exception-band phrases — no uppercase state names were invented for the band). I checked the ASCII diagrams' connector columns character-by-character: the booking branch pipes (cols 3/17/38) and the laundry exception-band pipes (under RECEIVED/WASHING/DRYING/PRESSING/QA_PACKAGING) match the encoded edges exactly. No invented edges; no missing drawn edges except the cross-aggregate arrow covered by RV-007. The stray `+` at the right end of the exception band aligns under PICKED_UP with no vertical bar drawn; the code's "no connector from READY/PICKED_UP" reading is the strict one and is corroborated by KBR-TXN-005 TV2 (READY cancellation blocked) and KBR-LND-005 (post-release incidents are custody incidents, not branches).
2. **KBR-LND-003 forward-only.** Single-successor chain, all skips/backwards absent from the table and denial-tested.
3. **KBR-LND-004/005 bypass hunt — negative.** The only functions that can ever return `"READY"` or `"PICKED_UP"` are `markReady` and `completePickup`; the generic `transitionProduction` hard-throws on both targets even along the legal edge, so the role/precondition guards cannot be sidestepped within typed use of the package. The one runtime loophole found (mutable transition tables, RV-002) requires deliberately untyped mutation and is a hardening condition, not a spec violation. The one genuine contract gap is RV-001: the T4 guard omits the release-completeness precondition that KBR-LND-005 states explicitly — this is the condition that keeps this from being a clean PASS.
4. **Finalization boundary.** Only DRAFT and EXPIRED are pre-finalization; every state at/after CONFIRMED/FINALIZED throws from `assertNotFinalized`. Correct against §4 ("Finalization is the immutability boundary") and §1 principle 4, and exhaustively tested.
5. **Tests are honest.** Denials are asserted with specific error classes (and doc-citation regexes), each precondition flag is falsified individually, and terminal states are checked against every possible target — this is real negative coverage, not decoration. 64/64 pass under reviewer re-run; lint clean.
6. **Writer's ambiguity claim.** No ambiguity record file exists in-repo, so I verified the underlying claim directly: everywhere the docs are ambiguous (combined-label states, exception-band right terminus, cross-aggregate T1→RECEIVED arrow, absent OPEN state from KBR-TXN-007's derivation vocabulary, no return edges from ISSUE_HOLD/holds, partial-release policy), the code encodes only the strict drawn/stated content and cites the doc, and the still-open items remain in `REQUIRED_LAUNDRY_DECISIONS`. The claim "the code encodes only what the docs state" holds, with the single exception inverted: RV-001 is a place where the code encodes _less_ than the doc states.

Nothing found rises to blocking for a SCAFFOLDED→IMPLEMENTED-IN-DEV pure domain package. RV-001 must be resolved (code or recorded deferral) before any service binds `completePickup` to real custody release.
