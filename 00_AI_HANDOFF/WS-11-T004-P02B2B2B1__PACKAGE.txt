## 4. Core replacement rule

After this package, issuance must follow this authoritative decision tree under
one transaction and one assignment lock.

### No current outstanding code

Use the existing 0163 issuance behavior unchanged.

### Current ISSUED code is not due

Return the existing stable result:

OUTSTANDING

Do not:

- expire it;
- issue another code;
- change its expiry;
- append a replacement event.

### Current ISSUED code is due

1. delegate to `expire_terminal_provisioning_code_v1`;
2. require a successful or already-expired canonical result;
3. preserve the predecessor row as EXPIRED;
4. reassess issuance eligibility;
5. issue one new code row under the new idempotency key;
6. return the raw replacement code only from the call that created it.

### Existing terminal historical rows

Do not mutate:

- EXPIRED;
- REVOKED;
- LOCKED;
- REDEEMED

back to ISSUED.

A replacement is always a separate row.

### New idempotency key

Replacement issuance requires a new idempotency key.

Replaying the predecessor’s original issuance key must never create or identify
a replacement.
