# WS-09-T005 — Implement restart, recovery and append-only controls

| Field                 | Value                                                                                                                                                                                                                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Implement Hub-local migration controls (deterministic, restart-safe, checksum-controlled, forward-only, recoverable), append-only enforcement, the approved safety modes, and a development-grade backup/restore procedure                                                               |
| Authoritative sources | `kitluy-storehub-recovery-and-replacement-runbook-v1.0.0.md`; `kitluy-storehub-phase1-spec-v1.0.0.md` safety sections; KLD-FIN-001 (append-only); KLD-2026-07-26-002 Group 5 (`HUB_READ_ONLY` = 503, blocks mutations)                                                                   |
| Owned files           | Hub migration runner/controls; append-only triggers; safety-mode service; backup/restore scripts                                                                                                                                                                                         |
| Schema ownership      | Hub migration ledger relation; append-only triggers across all Hub schemas                                                                                                                                                                                                               |
| Invariants            | Migrations deterministic, transactional, checksum-controlled, forward-only for released versions; finalized payment, finance, custody and audit records append-only; corrections are compensating entries or new events                                                                  |
| Safety modes          | Hub read-only mode, disk pressure, migration failure, database corruption suspicion, configuration incompatibility, device revocation, expired actor session, clock anomaly. `HUB_READ_ONLY` blocks mutations while preserving policy-permitted reads. | Test requirements     | Restart, crash-before-commit, crash-after-commit, response-loss replay, outbox recovery, incomplete-command recovery, stale version, connection loss, disk-full simulation, read-only transition, backup/restore round trip                                                              |

| Rollback / reset      | Drop and re-apply from zero; restore from a verified backup                                                                                                                                                                                                                              |
| Status ceiling        | IMPLEMENTED-IN-DEV, development-grade backup/restore only. NO production-certified disaster recovery is claimed (that needs hardware and pilot evidence)                                                                                                                                 |
