# WS-09-T003 — Implement local payment and finance persistence

| Field                 | Value                                                                                                                                                                                                                                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objective             | Persist payment intents, attempts, confirmations, deposits, allocations, refund and void requests, settlement and reconciliation references, plus balanced finance journals with posting deduplication, in the Hub-local database                                                        |
| Authoritative sources | WS-09-T001 reconciliation record; KBR-PAY-001..009; KBR-FIN-001..009; DD Amendment-001 (finance relations, AMD-I1..I7); `@kitluy/payments` engine; KLD-2026-07-26-002 Group 5 (`PAYMENT_PENDING` = HTTP 202, non-terminal)                                                               |
| Owned files           | Hub-local migrations for `edge_payments` and `edge_finance`; Hub payment/finance repository adapters and command services                                                                                                                                                                |
| Schema ownership      | `edge_payments`, `edge_finance`                                                                                                                                                                                                                                                          |
| Invariants            | Money is integer minor units + explicit currency, no floats, no implicit conversion; finalized payment/finance history append-only; journals balanced per currency with ≥2 legs; source-deduplicated postings; corrections are compensating entries; no direct client writes to journals |
| Permissions           | Refund/void follow four-eyes where the approved policy requires it; thresholds remain open owner values and are NOT invented                                                                                                                                                             |
| Failure modes         | `PAYMENT_PENDING` never becomes paid without authoritative confirmation; duplicate confirmation yields one business effect; duplicate finance source posting rejected; unbalanced journal rejected; cross-Tenant account reference rejected                                              |
| Test requirements     | Payment and finance persistence tests; duplicate-confirmation and duplicate-posting probes; balanced-journal probes; reuse of the 40 payment-engine vectors                                                                                                                              |
| Evidence requirements | `docs/evidence/phase1/ws-09/WS-09-T003/`                                                                                                                                                                                                                                                 |
| Rollback / reset      | Drop and re-apply the Hub-local database from zero                                                                                                                                                                                                                                       |
| Status ceiling        | IMPLEMENTED-IN-DEV. No live provider integration; KHQR remains simulator-only (PAY-OD-001/BLK-006); chart of accounts remains fictional `DEV-*` (FIN-OD-001)                                                                                                                             |
